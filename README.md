# pacing

广告活动预算节奏规划库（纯内存，无持久化、无接口层）。上层直接调用
`pacing.Plan`，同时支持首次排期与周期结束前的剩余周期重排。

## 用法

```go
res, err := pacing.Plan(pacing.Request{
    Days: 90,                 // 周期总天数（含已结算天数）
    Caps: []int64{...},       // 未来每天的机构共享支出上限（可为 0）
    Campaigns: []pacing.Campaign{{
        Budget:   1_000_000,  // 总预算（美分）
        Strategy: pacing.StrategyFrontLoaded,
        Paused:   []bool{...}, // 未来每天是否暂停
        Actual:   123_456,     // 已结算累计实际支出（首次排期为 0）
    }},
})
```

- 已结算天数 = `Days - len(Caps)`；历史支出不可改变，历史各日偏差不参与优化。
- `res.Feasible == false` 表示无法同时满足每日上限、暂停与逐活动花完预算，
  不会返回少花预算、超限或延长周期的替代方案。
- 可行时 `res.Daily[i][t]` 为活动 i 在未来第 t 天的计划支出，
  `res.MaxDeviation` 为「累计实际+计划 vs 累计目标」逐日绝对差最大值的
  全局最小值（整数美分精确最优）。

## 方法

对每个候选偏差 D，把每个活动未来第 t 日末的累计计划支出约束在
`目标(t) ± D`（按实际支出平移）的窗口内，可行性转化为带上下界容量的
时间展开网络流问题；对整数 D 二分即得精确最优。目标曲线始终由原预算、
原周期与原策略决定，暂停或历史偏离不移动曲线；奇数天周期的中间一天
在两个半段中各占一半。

## 测试

```sh
go test ./...
```

覆盖：共享上限迫使活动互相让额度、奇数天周期历史超前/落后后的重排、
总容量足够但暂停集中导致的无解、小额案例与暴力求解器的全局最优对照、
逐日上限与逐活动预算守恒校验，以及 32 活动 × 90 天 × 完整预算范围的
耗时与内存验证（实测约 0.1s / 数 MiB，远低于 5s / 256MiB 限制）。
