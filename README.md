# pacing — 广告活动预算节奏规划库

纯内存、无接口层的 Go 库，为共享机构每日支出上限的一批广告活动规划未来每日支出。

## 能力

- `PlanInitial(days, activities, caps)`：首次排期，无历史支出。
- `Replan(days, settled, activities, actual, caps)`：剩余周期重排，已结算前 `settled` 天的累计实际支出不可改变。

## 规则要点

- 节奏策略：均匀 / 前置（前半段 60%）/ 后置（后半段 60%）；奇数天周期中间一天两半段各占半天。
- 累计目标按精确比例计算后向下取整到美分，只由原预算、原周期、原策略决定，暂停与偏离不移动曲线。
- 硬约束：暂停日支出为 0；每日各活动支出之和不超过共享上限（可为 0）；每活动历史+计划恰好等于总预算。
- 优化目标：最小化「所有活动 × 所有未来日末 |累计实际+累计计划-累计目标|」的最大值，返回该精确最优值；无可行计划时返回 `Feasible=false`，绝不返回少花/超限/延期的替代方案。

## 方法

二分整数偏差 + 带下界循环流可行性判定（Dinic）。所有容量为整数，
最大流整数定理保证解为整数，偏差为整数金额规则下的精确全局最优。

## 使用

```go
acts := []pacing.Activity{
    {TotalBudget: 100000, Strategy: pacing.StrategyFront, Paused: []bool{false, false, true, false, false}},
}
res, err := pacing.PlanInitial(5, acts, []int64{30000, 30000, 30000, 30000, 30000})
if err != nil { /* 输入不合法 */ }
if !res.Feasible { /* 无可行计划 */ }
// res.MaxDeviation 为最小最大偏差；res.Spend[i][j] 为活动 i 未来第 j 天支出
```
